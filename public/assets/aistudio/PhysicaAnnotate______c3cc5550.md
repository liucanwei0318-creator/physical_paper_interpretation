## 一、产品概览

**PhysicaAnnotate — 理论物理英文论文深度翻译与精准批注系统**

核心设计理念：针对理论物理科研人员，采用 **K1–K4 分级知识模型**，在中文翻译过程中自动剔除已知基础知识的冗余解释，重点拆解核心瓶颈。

| 知识等级 | 含义 | 颜色标识 |
|---------|------|---------|
| K1 | 读者已掌握核心 | 🟢 绿色 |
| K2 | 条件触发熟练 | 🔵 蓝色 |
| K3 | 陌生盲区 | 🟡 琥珀色 |
| K4 | 论文原创机制 | 🟣 紫色 |

## 三、发现的错误与缺陷

### 🔴 致命缺陷：翻译流水线完成后白屏崩溃 (White Screen of Death)

> [!CAUTION]
> 这是**最严重的问题**，会导致用户丢失所有已翻译进度，必须立即修复。

**现象**：当防截断翻译流水线完成全部 14 个小节（§0 到 §V）并准备渲染最终文稿时，React 应用发生致命未捕获异常，`#root` DOM 节点被完全清空，整页白屏。

**控制台报错**：
```
Uncaught TypeError: e.annotations is not iterable
    at index-C2OUT80t.js:11

Uncaught TypeError: Cannot read properties of undefined (reading 'join')
    at index-C2OUT80t.js:11
```

**根因分析**：
后端 `/api/translate-chunk` 接口在处理简短小节（如 Abstract）时，返回的 JSON 中 `annotations` 字段可能为 `undefined/null`，或批注对象的 `keySteps` 为 `undefined`。前端代码**完全缺乏空值保护**：

```javascript
// ❌ 缺陷代码
for (let n of e.annotations) { ... }    // annotations 可能为 undefined
n.keySteps.join(...)                      // keySteps 可能为 undefined
```

**修复方案**：
```javascript
// ✅ 修复后
for (let n of (e.annotations ?? [])) { ... }
(n.keySteps ?? []).join(...)
```

同时**必须**在 React App 顶层添加 `<ErrorBoundary>` 组件，防止渲染异常导致全站崩溃。

---

### 🟡 中等问题：API 路由 404

**现象**：前端发起 `POST /api/fetch-arxiv` 请求时直接返回 **HTTP 404**。

**影响**：虽然前端有备用拉取逻辑成功获取到论文内容，但该 404 错误会产生冗余错误日志，也说明后端路由配置不完整。

**修复建议**：检查后端路由注册，确保 `/api/fetch-arxiv` 端点正确部署；或在前端移除对该路由的调用。

---

### 🟡 中等问题：状态持久化缺失

**现象**：仅 `physica_custom_entries` 写入了 `localStorage`。待译论文正文、翻译进度等关键数据完全驻留在内存 React State 中。

**影响**：用户误刷新页面或遭遇上述白屏崩溃后，所有未导出的翻译进度**彻底丢失**，需从头重新生成（耗时 2.5–3 分钟）。

**修复建议**：将当前论文信息及已完成的分节翻译结果缓存到 `localStorage` 或 `IndexedDB`，支持刷新恢复。

---

## 七、修改建议优先级排序

### 🔴 P0 — 立即修复（阻断性问题）

1. **添加 React Error Boundary**  
   在 App 顶层与各 Step 视图包裹错误边界组件，发生渲染异常时展示友好重试界面，而非白屏崩溃。

2. **修复空值未保护的代码**  
   对 `annotations`、`keySteps` 等后端返回字段全部添加防御性空值处理（`?? []`、`?.` 可选链）。

3. **添加翻译进度持久化**  
   将已完成的分节翻译缓存到 `localStorage` / `IndexedDB`，支持页面刷新后恢复。

### 🟡 P1 — 短期优化

4. **修复 `/api/fetch-arxiv` 404 问题**  
   补全后端路由或移除前端冗余调用。

5. **移动端导航优化**  
   屏幕宽度 < 768px 时将 4 步标签折叠为下拉式或紧凑步骤条。

6. **长表格/代码块横向溢出处理**  
   移动端添加 `overflow-x: auto` 容器包裹。

### 🟢 P2 — 长期增强

7. **添加翻译历史记录**  
   支持查看和管理过去翻译过的论文。

8. **支持批量论文队列**  
   允许用户一次导入多篇论文排队翻译。

9. **添加协作功能**  
   支持团队共享知识模型和翻译结果。
